# 서버 구현 상세

## 처리 단계

1. 업로드 파일을 `uploads/`에 저장하고 OpenCV로 읽습니다.
2. YOLOv8n으로 person 클래스(`classes=[0]`)를 탐지합니다.
3. 탐지 신뢰도 0.5 미만의 box는 후처리에서 건너뜁니다.
4. box 폭·높이의 12%만큼 주변 여유를 둔 전체 crop과 그 높이의 45%에 해당하는 상반신 crop을 만듭니다.
5. RetinaFace 검출 후 얼굴 크기·경계·눈 간격 등의 품질 조건을 검사합니다.
6. ArcFace 임베딩을 등록 임베딩과 비교해 최소 cosine distance를 선택합니다.
7. 판별 결과를 이벤트로 변환하고 DB·결과 이미지·알림 로그를 저장합니다.
8. 활성화된 알림 채널에 daemon 스레드로 발송 요청을 수행합니다.

등록 이미지별로 품질 조건을 통과한 가장 큰 얼굴을 선택해 서버 시작 시 캐싱합니다. 입력 이미지에서는 각 crop의 유효 얼굴을 비교합니다. 모델 학습 코드가 아니라 사전 학습 모델을 활용한 추론·통합 코드입니다.

## API

| 메서드 | 경로 | 동작 |
|---|---|---|
| GET | `/` | 서버 정보·판별 기준 반환 |
| GET | `/health` | 등록 임베딩 수·기능 활성화·쿨다운 설정 반환 |
| POST | `/detect` | multipart 필드 `file`로 이미지 분석 |

일반 탐지 응답의 주요 필드는 다음과 같습니다.

| 필드 | 의미 |
|---|---|
| `image` | 저장된 이미지명 |
| `yolo_time_ms` | YOLO 호출에 소요된 시간 |
| `total_time_ms` | 응답 구성 시점까지 서버 처리 시간; 외부 알림 도착 시간은 포함하지 않음 |
| `detections[].person_idx` | YOLO box 순서에 따른 인덱스 |
| `confidence` | YOLO 사람 탐지 신뢰도 |
| `final_result` | Registered / Unknown / Unidentified / CropFailed |
| `distance` | 최저 cosine distance; 비교 불가 시 null |
| `detector`, `crop_type`, `matched` | 선택된 검출기·crop 종류·등록 파일명 |
| `event_type`, `alert_required` | 이벤트 종류·알림 대상 여부 |

이미지 디코딩 실패는 HTTP 400입니다. YOLO box가 없으면 `result: NoPerson`과 빈 `detections`를 반환하며 일반 탐지 응답과 일부 필드가 다릅니다. box는 있으나 모두 신뢰도 필터에서 제외되면 `detections`는 비어도 `NoPerson` 저장 분기는 실행되지 않습니다.

## 결과 저장

- 원본: `uploads/`
- 판별 표시 이미지: `results/annotated/`
- 비교용 crop: `results/debug_crops/`
- 알림 대상 텍스트 로그: `results/alerts/alert_log.txt`
- DB: `detection_log` 테이블

DB에는 그룹·모델·이미지명·인물 순번·신뢰도·최종 결과·거리·검출기·crop 종류·이벤트·알림 여부·메시지·결과 경로·탐지 시각을 저장합니다. 등록 이미지 파일명 `matched`와 bounding box 좌표는 현재 INSERT 컬럼에 포함되지 않습니다. DB 스키마 예시는 이 실제 INSERT 구문을 기준으로 구성했습니다.

## 현재 구현의 한계와 개선 후보

- `async def` 엔드포인트 안에서 모델 추론·파일 I/O·DB 저장을 동기 실행합니다. 알림만 별도 스레드이며 전체 분석 파이프라인이 비동기 작업 큐인 것은 아닙니다.
- 다중 인물 처리 시 같은 결과 이미지 경로를 덮어씁니다. 알림 스레드의 읽기 시점에 따라 사진에 표시된 box가 달라질 수 있습니다.
- 알림은 daemon 스레드이므로 서버 종료 시 전달 보장·재시도가 없습니다.
- DB 실패와 알림 실패는 출력 로그로 남으며 요청 전체 실패로 처리하지 않습니다.
- 업로드 파일명 처리, 용량 제한, 인증, 요청 제한, 저장 파일 정리 정책은 운영 배포 전에 보완할 부분입니다.
- `Unidentified`에는 중간 거리 구간뿐 아니라 얼굴 품질 미달·검출 실패·비교 예외도 포함됩니다.
- 초기 계획에 있는 ROI·체류 시간 분석과 웹 로그 조회 UI는 이 코드에 구현되어 있지 않습니다.

이번 정리에서는 원래 실험 결과와 동작을 보존하기 위해 서버의 실행 로직을 변경하지 않았습니다. 상단 쿨다운 설명과 얼굴 비교 함수의 오래된 0.50 주석만 실제 상수에 맞게 정정했습니다.
